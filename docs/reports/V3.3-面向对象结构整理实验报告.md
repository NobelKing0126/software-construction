## 当前源码结构

```text
src/
├─ dao/                  数据访问接口、DaoFactory
│  └─ impl/              三个 File*Dao 文件实现
├─ service/              业务接口、ServiceFactory
│  └─ impl/              三个 *ServiceImpl 单例实现
├─ entity/               用户、资源、预约实体与预约状态枚举
├─ exception/            业务异常基类与具体异常子类
├─ ui/console/           启动、控制台输入输出与会话分派
└─ utils/                文件读写与 Result<T>
```

本轮增加一个 ServiceFactory，源码从 35 个变为 36 个 Java 文件。三个文件 DAO 只迁移至 `dao.impl` 并补充接口导入，数据操作和单例初始化逻辑保持原样。DaoFactory 更新实现类导入，仍返回 DAO 接口。

ServiceFactory 与 DaoFactory 的组织方式一致：私有构造器，三个静态获取方法分别返回 UserService、ResourceService、ReserveRecordService。方法内部调用原实现类的 getInstance，不新增对象缓存，不批量提前初始化其他 Service。

ConsoleApplication 改为调用 ServiceFactory；控制台包不再导入 service.impl 或 dao.impl。启动仍先按用户、资源、预约的顺序加载 DAO，保持原加载失败提示，然后获取服务并装配控制台组件。

## Java 特性的实际落点

| 特性 | 当前项目中的体现 |
| --- | --- |
| 抽象 | 三个 DAO 接口和三个 Service 接口定义对外契约，具体实现分别归入 impl 子包。 |
| 封装 | 实体属性、DAO 集合和 Service 依赖保持 private；User 新增 matchesPassword，将密码比较放在对象内部；toString 不再包含密码字段。 |
| 继承 | 原有 PasswordErrorException 等具体异常继承 BusinessException，UI 可以按共同业务异常类型捕获。 |
| 多态 | UI 使用 Service 接口变量，Service 使用 DAO 接口变量；调用实例方法时执行实际实现类重写的方法。静态工厂调用本身不属于运行时多态。 |

例如，控制台通过 `UserService userService = ServiceFactory.getUserService()` 获取接口引用，随后调用 login，实际执行 UserServiceImpl.login。登录将密码校验委托给 `user.matchesPassword(password)`，不再自行读取密码后比较。

matchesPassword 使用 `candidate != null && candidate.equals(password)`，保持大小写和空格参与精确比较；null 输入或未设置密码不会匹配。登录原有的空值校验和注册的长度要求仍由 Service 负责，旧账号短密码登录兼容性保留。FileUtil 仍通过 getPassword 保存原文本格式。

明确的输出变化是 User.toString 移除了 password 字段，Result<User> 的字符串表示也因此不再经该路径输出密码。其他实体保持 JavaBean 结构；没有为展示关键字而增加空的抽象父类或用户子类，也未提前加入后续 MVC 功能。
