校园资源预约系统 V2.0 实验报告

实验任务
任务6：校园资源核心模块开发。在 V1.4 用户注册、登录、用户文件持久化和自定义业务异常的基础上，新增校园资源实体、资源集合、资源文件持久化和角色权限控制。管理员可以新增、查询、修改和删除资源；学生只能查询状态为 AVAILABLE 的资源。资源不存在、非法状态及权限不足时显示中文业务提示，不打印原生异常堆栈。

设计与实现
新增 CampusResource 实体，包含 id、name、type、status、location、description 六个私有字段、无参构造、全参构造、get/set 方法和 toString 方法。该类只承载资源数据。程序使用 List<CampusResource> 保存全部资源对象。

FileUtil 新增 loadResources 和 saveResources。程序启动时读取 resource.txt；文件缺失时自动创建。新增、修改、删除后保存六个字段，使用 UTF-8 和 try-with-resources。字段分隔符、反斜线和换行按现有用户文件工具的转义规则读写。

SystemMain 在登录成功后根据 User 的角色进入管理员或学生菜单。管理员可新增资源，系统生成 UUID 资源编号并将状态设为 AVAILABLE；可查询全部资源；修改时按编号查找并仅接受 AVAILABLE、OCCUPIED、DISABLED 三种状态；可按编号删除。学生菜单只列出 AVAILABLE 资源，新增、修改、删除入口也会检查管理员权限。新增和修改时资源名称不能为空。

新增 ResourceNotFoundException、InvalidResourceStatusException 和 PermissionDeniedException，均继承 V1.4 的 BusinessException。资源菜单捕获业务异常并显示中文提示；资源文件读写失败显示中文错误信息。

预约记录删除限制说明
检查 V1.4 的实际源文件后，未发现 ReserveRecord 实体、预约记录集合、预约数据文件或预约功能。V2.0 按要求未新增预约业务，因此当前版本没有已有预约记录可供删除前校验。此版本按资源编号完成删除；“存在预约记录的资源禁止删除”在当前数据结构下无法验证，待预约记录功能加入后再按实际记录执行该限制。

问题与处理
实现前在隔离目录运行 V1.4 基线，管理员登录成功后只返回登录、注册主菜单，尚无资源管理菜单；该基线检查按预期失败。实现后同一登录流程进入角色菜单。

验证宿主的 Windows PowerShell 不支持 ProcessStartInfo.StandardInputEncoding 属性。控制台测试脚本改为向 Java 进程的标准输入流写入 UTF-8 字节后重新执行，中文测试输入和输出均正确。删除用例的一条初始断言包含了删除前查询的输出，随后将断言范围改为删除成功后的查询输出；应用程序删除成功提示和删除后数据均通过检查。以上问题均通过调整验证方式处理，没有为此修改业务代码。

工作思路总结
先核对任务6原文、评分要求、Git 状态和 V1.4 的 User、FileUtil、SystemMain 及业务异常实现，确认不重构现有结构，并确认 V1.4 尚无预约记录数据。随后在现有工具类中增加资源文件读写，在入口中增加按角色展示的资源菜单和业务异常处理。最后使用 Temurin JDK 8 编译，在隔离目录以真实控制台输入检查管理员资源增删改查、学生资源过滤与权限、异常提示、资源重启加载以及原有注册登录流程，并在验证后清理临时文件。
