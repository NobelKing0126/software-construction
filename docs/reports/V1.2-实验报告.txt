V1.2 实验报告：面向对象封装与 User 实体类重构

一、实验目标

按照任务3，将 V1.1 中仅保存账号和密码的用户集合重构为 List<User>，通过 User 实体承载账号、密码、角色和注册时间。实体类只保存数据，不包含注册或登录业务逻辑。

二、设计与实现

新增 User 类，字段为私有的 username、password、role 和 registerTime。注册时间使用 Java 8 的 LocalDateTime。类提供无参构造、包含全部字段的有参构造、所有字段的 getter/setter，以及打印全部字段的 toString()。

SystemMain 使用 List<User> 和 ArrayList<User> 在内存中保存用户。按账号查找用户的逻辑留在 SystemMain；登录继续校验账号和密码，注册继续执行账号非空、密码至少6位和账号唯一性校验。新注册用户的角色设为 student，注册时间取当前时间。注册成功后打印用户对象，供检查各字段是否完整。

本版本仍为内存存储，没有加入文件持久化或自定义异常。

三、测试输入与实际结果

依据项目要求，使用 Temurin JDK 8 实际编译 src\User.java 和 src\SystemMain.java。编译成功，命令退出码为 0，无编译错误。编译输出目录 .v1.2-verify 在验证后已清理。

场景一：注册学生账号
输入：选择 2，账号 alice，密码 123456。
实际结果：输出“注册成功。”，随后打印：
User{username='alice', password='123456', role='student', registerTime=2026-11-02T10:28:38.038}
四项信息均有输出，时间由程序实际生成。

场景二：重复注册
输入：再次使用账号 alice、密码 123456 注册。
实际结果：输出“账号已存在，注册失败。”

场景三：注册后登录
输入：使用账号 alice、密码 123456 登录。
实际结果：输出“登录成功，欢迎使用校园资源预约系统！”

场景四：短密码校验
输入：注册账号 bob，密码 12345。
实际结果：输出“密码不能为空且长度不能少于6位。”

场景五：未注册账号登录
输入：使用账号 bob、密码 123456 登录。
实际结果：输出“账号或密码错误，登录失败。”

场景六：空账号校验
输入：注册账号留空，并按提示输入密码行。
实际结果：输出“账号不能为空。”，随后正常退出。

四、问题与处理

首次运行命令在嵌套 PowerShell 调用中没有将 -Dfile.encoding=UTF-8 作为单个 JVM 参数传入，程序未启动；将参数整体加引号后，运行验证正常完成。

空账号场景的注册流程会先读取账号和密码，再执行校验。第一次测试输入只提供了空账号，未提供密码行，导致输入流提前结束；按现有交互补充密码行后，空账号校验通过。此处只是测试输入与程序提示不匹配，没有改动 V1.1 的交互流程。
