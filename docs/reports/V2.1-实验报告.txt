校园资源预约系统 V2.1 实验报告

实验任务
任务7：统一返回结果封装 Result。基于 V2.0 为用户和资源业务方法统一返回成功标志、中文提示和数据；控制台读取结果并显示提示；保留自定义业务异常、原有权限规则、资源增删改查和文件持久化。本版本不新增预约、数据库、分层或任务8的函数式查询。

设计与实现
实际使用 C:\Users\22614\AppData\Local\Programs\Temurin8\jdk8u504-b01\bin 下的 javac.exe 和 java.exe。javac 输出为 1.8.0_504，java 输出为 openjdk 1.8.0_504、Temurin build 1.8.0_504-b01。编译源文件时使用 -encoding UTF-8，运行时使用 -Dfile.encoding=UTF-8；类文件和控制台测试数据位于隔离的系统临时目录。

新增 Result<T>，保存 success、msg、data，提供 get/set、toString 及四种 success/fail 工厂方法。失败结果的 data 为 null；setter 将结果设为失败时也清空 data。Result 不判断业务规则，也不读写文件。

SystemMain 中注册、登录、按用户名查询、按 ID 查询资源、资源新增、列表查询、修改、删除均返回 Result<T>。新增和修改返回 CampusResource，列表查询返回 List<CampusResource>，删除返回 Result<Void>。控制台读取 isSuccess、getMsg、getData；成功时显示提示和必要数据。业务校验继续使用 V1.4 的 BusinessException 及其子类，在菜单调用边界转换成 Result.fail 后输出中文提示；IO 错误也使用中文提示。FileUtil、User、CampusResource 和异常类未改动。

验证准备
在系统临时目录准备管理员记录 admin|admin123|admin|2026-11-12T10:00:00。资源文件由程序在临时目录创建。该记录的 role 是 admin。另设隔离目录，以用户名 admin、role 为 student 及用户名 manager、role 为 admin 的记录验证权限依据角色字段。项目根目录已有的 user.txt 和 resource.txt 未用于测试，也未被改写。验证结束后，临时编译文件及测试数据已清理。

测试输入与实际输出
所有编译和 Java 验证进程退出码均为 0，标准错误为空；控制台未出现原生异常堆栈。

Result 工厂方法：测试程序依次调用 success(7)、success("仅提示")、success("带数据", 8)、fail("失败原因")。实际输出分别为 Result{success=true, msg='操作成功。', data=7}、Result{success=true, msg='仅提示', data=null}、Result{success=true, msg='带数据', data=8}、Result{success=false, msg='失败原因', data=null}。将失败结果设置非空 data，以及将带数据结果改为失败后，实际输出“失败结果 data 仍为 null”。

管理员新增和查询：输入 1、admin、admin123；两次选 1，分别输入“一号会议室 / 教室 / 主楼101 / 描述一”和“二号会议室 / 会议室 / 主楼102 / 描述二”；选 2 查询全部资源。实际输出两次“资源新增成功”，生成 ID 分别为 5f47af5e-9749-4ff6-9fc9-9de206dfc534 和 4a04f235-d0de-450d-b423-b0d43b5e1837；“查询全部资源成功。”后显示两条资源，状态均为 AVAILABLE。

重启修改及失败提示：重新登录管理员，将第二条资源状态改为 OCCUPIED；按 missing-id 分别尝试修改和删除；将第一条资源状态尝试改为 BAD_STATUS；尝试新增空名称资源，最后查询全部。实际输出“资源修改成功。”、“资源不存在，无法修改。”、“资源不存在，无法删除。”、“资源状态不合法，只能是 AVAILABLE、OCCUPIED 或 DISABLED。”及“资源名称不能为空。”。查询仍显示第一条名称为一号会议室、状态 AVAILABLE，第二条状态 OCCUPIED，说明非法修改未覆盖原数据。

注册、登录及学生权限：输入注册 newstudent / student1，随后重复注册同名账号、使用 123 注册短密码、使用空账号注册；再分别以不存在账号、错误密码、空账号、空密码登录，最后以 newstudent / student1 登录并选择查询及菜单选项 2、3、4。实际依次出现“注册成功。”、“账号已存在，注册失败。”、“密码不能为空且长度不能少于6位。”、“账号不能为空。”、“用户不存在，登录失败。”、“密码错误，登录失败。”、“账号不能为空。”、“密码不能为空。”及登录成功提示。学生查询仅显示 AVAILABLE 的一号会议室，没有显示 OCCUPIED 的二号会议室；三次越权尝试均显示“权限不足，仅管理员可以管理校园资源。”。

删除与重启加载：管理员按 ID 4a04f235-d0de-450d-b423-b0d43b5e1837 删除第二条资源，再查询全部；实际输出“资源删除成功。”，查询仅有一号会议室。再次重启后，newstudent 可以登录并查询一号会议室，管理员也可登录并查询同一条资源；已删除的第二条未恢复。临时目录最终 user.txt 有两条记录，resource.txt 有一条记录。

角色和文件错误：在单独测试目录中，以用户名 admin、role 为 student 的账号登录，实际进入学生菜单，选择 2 显示权限不足；以用户名 manager、role 为 admin 的账号登录，实际进入管理员菜单并可查询全部资源。另在隔离目录分别准备格式错误的 user.txt 和 resource.txt 启动程序，实际输出“用户数据加载失败，请检查 user.txt。”和“资源数据加载失败，请检查 resource.txt。”，退出码均为 0。

问题与处理
按 ID 修改资源时沿用 V2.0 的交互顺序：先输入 ID，若不存在便立即提示，而不继续索取新字段。控制台输入方法先读取 Result 查询结果，再调用返回 Result 的修改方法；业务方法本身仍再次确认 ID 与管理员权限。控制台打印成功提示的位置统一移到结果展示处，避免业务方法和菜单重复打印。

工作思路总结
先核对任务7原文、验收标准、评分要求和 V2.0 的方法返回值、异常与文件流程。只新增结果类并调整 SystemMain 的业务返回值和菜单展示方式，不改实体、文件格式或包结构。随后用指定的 Temurin JDK 8 编译，在隔离目录以真实控制台输入验证结果封装、管理员操作、学生权限、失败提示和重启持久化，最后清理验证产物。
