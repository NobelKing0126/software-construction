V3.0 资源预约核心业务实验报告

工作思路总结
本版本以 V2.2 提交 d23393c5a54531d319050c055049914ec59372fa 为起点，先核对课程任务9原文及验收标准，再检查现有登录、资源查询与增改删、Result、异常捕获和文本文件转义规则。保持不分包的阶段结构，在原有控制台流程中增加预约入口；先在项目内独立目录编写真实输入测试，再增加实体、文件读写和业务方法，最后验证完整申请、审核、取消闭环及 V2.2 回归。未引入任务10的三层架构和其他扩展功能。

设计与实现
实际使用 C:\Users\22614\AppData\Local\Programs\Temurin8\jdk8u504-b01\bin\javac.exe 和 java.exe；版本输出分别为 javac 1.8.0_504、openjdk version "1.8.0_504"。编译命令对全部 src/*.java 指定 -encoding UTF-8，输出放在项目内临时目录；编译标准输出和标准错误均为空，退出码 0。Java 进程均以隔离测试目录为工作目录，使用 -Dfile.encoding=UTF-8，未读取或写入项目根目录已有的 user.txt、resource.txt 及 .v22-isolated-demo。

新增 ReserveStatus 枚举，值为 PENDING、PASS、REJECT、CANCEL；ReserveRecord 保存唯一 recordId、resourceId、applicantUsername、三个 LocalDateTime 时间、状态和可选备注，仅承担数据存储。预约记录使用 List<ReserveRecord>，新建、审核和取消后写入 reserve.txt，程序启动时读取，文件不存在则创建。文件为 UTF-8，每行依次是 recordId|resourceId|applicantUsername|applyTime|reserveStartTime|reserveEndTime|status|remark，共八个字段；时间采用 LocalDateTime 的 ISO 文本，例如 2026-12-14T10:00，备注留空时最后一个字段为空。沿用 FileUtil 的转义规则：竖线写为 \|，反斜杠写为 \\，换行写为 \n，回车写为 \r；读取时反向还原。读写流使用 try-with-resources。user.txt 和 resource.txt 原有格式及读写代码未改。

学生菜单新增 10 提交预约、11 查询我的预约、12 取消我的预约；管理员菜单新增 7 查询全部预约、8 按记录 ID 审核、9 按资源 ID／申请人／状态筛选。预约列表使用 Stream 和 Lambda 过滤，按记录 ID 查找使用 Stream.findFirst 与 Optional，业务结果继续返回 Result<T>；失败抛 BusinessException 体系异常，在菜单层显示中文提示。Result 四种工厂方法未改。管理员不能提交或取消个人预约，学生不能审核或查询全部预约，也不能取消他人的记录。

时间输入格式为 yyyy-MM-dd HH:mm。提交时要求开始早于结束、结束时间不早于当前时间、资源状态为 AVAILABLE。冲突判定采用左闭右开区间［开始，结束），条件是新开始早于已有 PASS 的结束且已有 PASS 的开始早于新结束；两段只在端点相接不冲突。管理员审核通过时再次检查，避免多个待审申请先后通过后重叠。通过后资源置 OCCUPIED，驳回不改资源；只允许 PENDING 审核。取消 PENDING 或 PASS 后变为 CANCEL，REJECT 和 CANCEL 不可再次取消。一个资源若有多条时间不重叠的 PASS，取消其中一条时仍保持 OCCUPIED，最后一条 PASS 取消后恢复 AVAILABLE。已有 PASS 时禁止把资源手动改为其他状态或删除；仅有 PENDING、REJECT、CANCEL 时仍可删除。若待审记录关联的资源后来被删除，审核通过会给出“关联资源不存在，无法审核通过。”，该记录仍可驳回。

预约状态与资源状态需要分别写入两个文本文件。测试只读文件失败路径后，修改为先保存预约、再保存资源；写入失败时恢复内存原状态，资源写入失败且预约已保存时尝试把预约文件写回原状态，并显示对应中文提示。普通文件读写不提供跨文件原子事务；若发生断电或两个文件同时无法写入，仍需人工检查文件。

遇到的问题及处理
测试脚本最初把同一时刻的起止时间用于“结束时间已过期”场景，程序先按规则报告“开始时间必须早于结束时间。”；改用相差一天的过去时间后，得到预期的结束时间提示。端点相接的测试起初也把资源状态影响误写成时间冲突预期；随后分别测试时间边界和 OCCUPIED 状态，明确了两种约束的先后。只读文件测试发现审核写入失败时内存与文件可能不同步，因此增加状态恢复和可恢复文件的回写，再次运行相关测试通过。
