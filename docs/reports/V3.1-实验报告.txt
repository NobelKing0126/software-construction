本版本以 Git 提交 645b84db1a706069a57e0a35cda6febdc07f27ef（v3.0）为基线，只重构分层与包结构。工作目录为 C:\Users\22614\Desktop\大三上\软件构造\校园资源预约系统。
实际编译、运行使用 C:\Users\22614\AppData\Local\Programs\Temurin8\jdk8u504-b01\bin\javac.exe 和同目录 java.exe。实际版本输出：javac 1.8.0_504；openjdk version "1.8.0_504"，Temurin build 1.8.0_504-b01。递归编译 src 下全部 UTF-8 Java 源文件，指定 -encoding UTF-8；运行入口为 ui.console.SystemMain，指定 -Dfile.encoding=UTF-8。编译产物和每个场景的数据仅放在项目内独立临时目录，Java 的工作目录为对应场景目录；未用项目根目录既有的 user.txt、resource.txt、reserve.txt。

二、迁移前后职责与依赖
V3.0 的默认包 SystemMain 同时处理 Scanner、菜单、登录注册、资源 CRUD、预约流程、权限和时间校验、集合管理及 FileUtil 调用。V3.1 将入口和所有交互展示迁至 ui.console.SystemMain；UserService、ResourceService、ReserveRecordService 分别处理用户、资源、预约业务规则及资源状态联动；dao 包管理内存集合、查找增删和调用 FileUtil 读写；entity 保存 User、CampusResource、ReserveRecord、ReserveStatus 数据；exception 保存原有自定义异常；utils 保存 FileUtil 和 Result<T>。菜单编号、中文提示、Result<T> 约定、四种预约状态、时间边界以及三种文本文件格式保持 V3.0 行为。
业务调用方向为 UI → Service → DAO 接口 → 文件 DAO → FileUtil。三个最小接口分别为 UserDao（按账号查找、添加、保存）、ResourceDao（列表、按 ID 查找、添加、删除、保存）、ReserveRecordDao（列表、按 ID 查找、添加、删除、保存）；FileUserDao、FileResourceDao、FileReserveRecordDao 各自实现一个接口。Service 通过构造器接收接口；只有 SystemMain.main 启动装配处创建具体文件 DAO 和 Service，菜单业务不访问 DAO。没有引入通用 BaseDao、单例或工厂。DAO 不判断权限、预约冲突或审核结果；Service 不直接调用 FileUtil；Scanner 与菜单打印只在 ui.console。控制台输入的时间字符串交由 ReserveRecordService 解析。
预约审核通过或取消已通过预约涉及 reserve.txt 与 resource.txt 两次保存。V3.1 保留 V3.0 的恢复流程：先记旧预约状态和资源状态，保存预约后保存资源；若失败则恢复内存对象，预约已写入时再尝试写回旧状态，并给出对应中文失败提示。该流程不是跨文件原子事务，恢复再次写入失败仍会提示“数据保存失败且预约状态恢复失败，请检查 reserve.txt 和 resource.txt。”。

四、真实回归记录
数据基线：通常用 admin/password/admin、alice/password/student、bob/password/student，注册时间均为 2026-01-01T00:00；资源初值为 r-a 自习室 AVAILABLE、r-b 会议室 AVAILABLE、r-c 机房 DISABLED。预约场景按需要预置 PENDING、PASS、REJECT、CANCEL 记录。以下方括号逐项表示送入 stdin 的一行，每次输入末尾也有换行；“重启”表示另起 Java 进程、沿用该场景写出的文件。stdout 为实际输出摘录，完整菜单提示也在实际 stdout 中。全部 14 个场景共 20 次进程运行，逐次 stderr 均为空字符串，退出码均为 0。V3.0 与 V3.1 逐场景比较 stdin、stdout、stderr、退出码及三个文件快照，仅将随机 UUID 和当前时间规范化，比较结果均相同。

01 登录、注册、重启：
输入1 [2, charlie, password, 1, charlie, wrong, 1, charlie, password, 0, 0]；stdout 摘录：“注册成功。”“密码错误，登录失败。”“登录成功，欢迎使用校园资源预约系统！”；user.txt 实际新增 charlie|password|student|2026-11-14T13:36:45.603。
输入2 [1, charlie, password, 0, 0]；重启后 stdout 仍为“登录成功，欢迎使用校园资源预约系统！”，user.txt 保留 charlie 行。

五、问题、处理与边界
读取任务书 DOCX 的 OOXML 正文时，首次在 Windows 默认 GBK 输出下遇到文档中符号无法编码；改为 UTF-8 标准输出后完成只读提取。迁移中需要让 UI 保留原先“先校验资源 ID，再询问修改字段”的交互顺序，因此将这一步校验交给 ResourceService；时间格式校验移到 ReserveRecordService，输入顺序和提示未改变。类图初次渲染时依赖箭头交叉较多，调整包布局并精简重复连线后重新渲染、查看 PNG。双文件保存失败用场景 13、14 的实际运行检验了中文提示和可恢复状态。
本版本未添加任务11的 rejectReason、auditTime 或新状态机实现；未添加任务12的饿汉单例、getInstance()、DaoFactory；未添加任务13的 view、controller、enums、common、ResourceStatus 或 MVC 图；未增加数据库、统计、日志和网页界面。
未制作或声称存在截图。XMI 是否被特定 Visual Paradigm 版本无损导入尚待在该软件中验证。本版本提交号见 Git 版本记录。
