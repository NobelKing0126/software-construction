三、设计与实现

V3.2 对象创建链路：
SystemMain 调用 ConsoleApplication.start；ConsoleApplication 依次 new FileUserDao、FileResourceDao、FileReserveRecordDao。
三个 DAO 构造器调用 FileUtil.loadUsers/loadResources/loadReserves 将文件读入各自的 final List 字段。
随后通过 new UserService(users)、new ResourceService(resources, records)、new ReserveRecordService(records, resources) 注入 DAO，再构造 ResourceConsole、ReserveConsole、ConsoleSession。

V3.3 调整：
1. UserService、ResourceService、ReserveRecordService 以 private static final INSTANCE = new 本类() 创建唯一实例；构造器私有，提供 public static getInstance()。
2. FileUserDao、FileResourceDao、FileReserveRecordDao 以 private static final INSTANCE 保存实例，在类的静态初始化块中调用唯一的私有构造器；提供 public static getInstance()。
3. 新增 dao.DaoFactory，只有私有构造器及三个静态工厂方法。返回类型是 UserDao、ResourceDao、ReserveRecordDao 接口，方法内部仅调用对应 File*Dao.getInstance()。没有批量初始化 DAO 的静态字段。
4. 三个 Service 的 final DAO 字段仍使用接口类型，私有构造器通过 DaoFactory 获取依赖。Service 之间没有相互依赖。
5. ConsoleApplication 先依次调用三项加载方法，全部成功后才获取三个 Service 单例并装配原有 UI 对象。

四、初始化顺序与异常处理

启动顺序保持为：用户 DAO → 资源 DAO → 预约 DAO → Service → 会话。
三个 DAO 的私有构造器继续声明 throws IOException，加载逻辑原样保留。静态初始化块只捕获 IOException，并用 ExceptionInInitializerError 保留原因。
例如非法用户时间产生的 RuntimeException 会由 JVM 包装为类初始化错误；因此启动加载边界将原 catch (Exception) 扩为 catch (Exception | ExceptionInInitializerError)。没有捕获 Throwable 或 Error 大类。

各加载边界继续转换为原 BusinessException 提示，由 start 输出后立即返回：
用户数据加载失败，请检查 user.txt。
资源数据加载失败，请检查 resource.txt。
预约数据加载失败，请检查 reserve.txt。

任一步失败都不进入后续加载方法，也不获取 Service。没有改为空集合继续运行，没有自动修复或覆盖坏文件，没有重试。
缺失文件仍由 FileUtil 在原加载时机创建；失败前尚未轮到的缺失文件不创建。
类初始化失败后不在同一 JVM 恢复该类，恢复测试使用修复后的测试文件与新进程。

六、实际遇到的问题与解决

1. 静态字段初始化不能直接忽略 DAO 构造器的 IOException。采用类内静态初始化块，将失败转成 ExceptionInInitializerError，启动边界明确处理该类型，避免原 catch (Exception) 漏接。
2. Windows 下 javac 负向编译诊断包含中文路径，默认编码使测试脚本按 UTF-8 解码失败。负向编译增加 -J-Dfile.encoding=UTF-8，并指定英文诊断，重新验证六个构造器均确因私有访问被拒绝。
3. 控制台基线测试最初将“查询资源成功。”的子串出现次数写为1，但它也出现在“按名称查询资源成功。”中，实际为2。修正准确预期为2，保留完整消息断言，并完整重跑两版；没有改生产提示。
4. 代码审查发现测试比较器直接 zip 两版结果可能漏掉尾部场景，补充完整列表和数量校验后重新比较，结果仍全部一致。
5. 二进制 Git 归档最初经命令输出代理捕获后不能解压，改用 git archive --output 直接写入本次临时目录，重新解压并成功编译冻结源码。
6. 远程标签只读核实最初遇到 Schannel 凭据错误，改用单次命令参数 -c http.sslBackend=openssl 查询成功；没有修改持久 Git 配置，没有推送。
