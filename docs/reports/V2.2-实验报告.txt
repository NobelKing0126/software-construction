V2.2 函数式编程实验报告

工作思路总结
本版本以 v2.1（ad3c232）为起点，只调整资源查询和控制台查询入口。先核对任务8原文：必做项是 Stream 与 Lambda 筛选可预约资源、名称包含查询、按资源 ID 自然升序排列，以及用 Optional 处理按 ID 查找时的不存在情况；通用多条件组合查询和名称忽略大小写属于可选内容，本版本未扩展。修改后在隔离目录准备账号与资源，使用真实控制台输入验证查询、权限、文件加载，再将原版与新版的新增、修改、删除及持久化结果对照。

设计与实现
实际使用 C:\Users\22614\AppData\Local\Programs\Temurin8\jdk8u504-b01\bin\javac.exe 和 java.exe，版本输出分别为 javac 1.8.0_504、openjdk version "1.8.0_504"；编译源文件指定 -encoding UTF-8，运行指定 -Dfile.encoding=UTF-8。编译标准输出、标准错误均为空，退出码为 0。
管理员“查询全部资源”从资源流取得全部数据；学生“查询可预约资源”用 filter 筛选 status 为 AVAILABLE。两者与名称查询共用一处查询结果收尾逻辑：按 ID 升序排序、收集为独立 List，再根据是否为空选择原有中文提示。新增菜单 5“按名称查询资源”和 6“按 ID 查询资源”，两种角色使用同一编号。名称查询采用 name.contains(关键词)，学生先按角色过滤，仅能得到 AVAILABLE 资源；空关键词给出中文提示。单资源查找使用 Stream.findFirst 得到 Optional<CampusResource>，仅在 isPresent 后取值，并继续用 Result<CampusResource> 返回“查询资源成功。”或“未找到该 ID 对应的资源。”；学生按 ID 查询 OCCUPIED、DISABLED 时也得到同一未找到提示。原有 Result 四种工厂方法、业务异常捕获、用户模块、资源增改删、文件格式和读写流程均未修改。

代码量复核
针对验收标准中的“代码行数大幅精简”，本次将三处列表查询重复的排序、收集和空结果判断合并后，SystemMain.java 相对上一条 V2.2 提交净减少 7 行，资源集合查询中的旧 for 循环已消除。与 V2.1 相比，整个文件仍净增加 41 行，因为任务8同时新增了关键词查询、单资源详情入口及相应权限处理，不能把总文件行数说成大幅缩短。旧查询的可见状态范围、成功/空结果提示保持一致；展示顺序按任务8新增要求改为 ID 升序。

测试输入与实际输出
隔离测试数据：user.txt 含 admin/password/admin、student/password/student、guest/password/guest；resource.txt 按 r-20(AVAILABLE)、r-11(OCCUPIED)、r-03(AVAILABLE)、r-01(DISABLED) 的乱序写入，四项名称均以“自习室”开头。测试目录在项目内临时创建，运行后已清理；项目现有 user.txt、resource.txt 未改写。下面各输入以“→”表示依次按回车，记录的是控制台实际输出中的关键行。

管理员查询输入：1→admin→password→2→5→自习→6→r-11→6→r-99→0→0。
实际输出：查询全部资源成功。资源 ID 依次为 r-01、r-03、r-11、r-20，包含 DISABLED、AVAILABLE、OCCUPIED；按名称查询资源成功。结果 ID 仍依次为 r-01、r-03、r-11、r-20；按 r-11 查询输出“查询资源成功。”及 status='OCCUPIED' 的资源详情；按 r-99 查询输出“未找到该 ID 对应的资源。”。标准错误为空，退出码 0。

学生查询输入：1→student→password→1→5→自习→5→篮球→5→空行→6→r-03→6→r-11→6→r-01→6→r-99→2→3→4→0→0。
实际输出：“查询可预约资源成功。”下仅有 r-03、r-20，且按该顺序排列；“自习”名称查询也仅有 r-03、r-20；“篮球”输出“未找到匹配的资源。”；空关键词输出“资源名称关键词不能为空。”；r-03 输出“查询资源成功。”及 AVAILABLE 详情；r-11、r-01、r-99 均输出“未找到该 ID 对应的资源。”，未显示受限资源详情；尝试原管理员操作编号 2、3、4 各输出一次“权限不足，仅管理员可以管理校园资源。”。标准错误为空，退出码 0。

无权限角色输入：1→guest→password→0。实际输出“当前账号角色无资源操作权限。”，无异常堆栈；标准错误为空，退出码 0。

原版与新版持久化对照：两版均从相同隔离数据启动。新增输入为 1→admin→password→1→临时场地→教室→五楼→测试→0→0；V2.2 输出“资源新增成功”，resource.txt 新增行实际为 f0b94bd9-8d84-416f-8df9-2e27ac98ad2e|临时场地|教室|AVAILABLE|五楼|测试。重启后管理员查询能看到该资源。修改输入为 1→admin→password→3→f0b94bd9-8d84-416f-8df9-2e27ac98ad2e→临时场地改→教室→六楼→OCCUPIED→0→0；输出“资源修改成功。”，文件对应行变为 f0b94bd9-8d84-416f-8df9-2e27ac98ad2e|临时场地改|教室|OCCUPIED|六楼|测试；重启后可查询该状态。删除输入为 1→admin→password→4→f0b94bd9-8d84-416f-8df9-2e27ac98ad2e→0→0；输出“资源删除成功。”，文件恢复为最初四行，重启查询不再显示该资源。v2.1 对照运行的随机 ID 为 9e657127-a275-47ab-9e5d-112bcdebb99d，新增、修改、删除提示和去除随机 ID 后的持久化字段与 V2.2 一致；全量查询展示顺序按任务8要求改为 ID 升序。

用户重启加载输入：2→newstudent→password→0，实际输出“注册成功。”，隔离 user.txt 出现 newstudent|password|student| 开头的记录；重启后输入 1→newstudent→password→1→0→0，实际输出“登录成功，欢迎使用校园资源预约系统！”及“查询可预约资源成功。”，仅显示 r-03、r-20。原版与新版表现一致。上述查询及对照共 19 次 Java 进程运行，标准错误均为空，退出码均为 0。

精简后的复核：重新用同一 Temurin JDK 8 的 javac.exe 指定 -encoding UTF-8 编译，退出码 0，标准输出和标准错误均为空。另在隔离目录运行 10 次 Java 进程。管理员全量及“自习”名称查询均按 r-01、r-03、r-11、r-20 输出；学生列表和“自习”查询均只按 r-03、r-20 输出；“篮球”输出“未找到匹配的资源。”，空关键词输出“资源名称关键词不能为空。”，受限 ID 与不存在 ID 均输出“未找到该 ID 对应的资源。”，学生尝试管理员原操作编号 2、3、4 均得到原有权限不足提示。空资源文件下，管理员全量查询输出“当前没有校园资源。”，学生列表输出“当前没有可预约资源。”，名称查询输出“未找到匹配的资源。”。新增资源后重启可见，修改后重启保留 OCCUPIED，删除后文件恢复最初四行且重启不再显示该资源。本轮 10 次进程标准错误均为空、退出码均为 0，隔离编译产物和测试数据已清理。

遇到的问题及处理
首次由终端转发打印测试记录时中文显示乱码；将记录程序的标准输出明确设为 UTF-8 后重跑，控制台消息正确显示，Java 进程的标准错误始终为空。新增资源 ID 由 UUID 随机生成，两次对照运行的值自然不同，因此按相同输入、业务提示与去除 ID 后的文件字段比较，而不把 ID 值差异当作行为变化。
